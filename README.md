# Orbit — Personal AI Workspace

A responsive, dark-themed website starter for a screen-aware, voice-enabled personal productivity agent.

**Repository:** https://github.com/varun5812/Fit_Tracker

## Features in this starter

- **Overview dashboard** with task, note, focus-session, and connection summaries.
- **Assistant chat UI** with local rule-based demo responses and suggested prompts.
- **Voice interface** using browser speech recognition and text-to-speech where supported.
- **Screen sharing** through the browser's native display-capture permission picker, with an active preview and stop control.
- **Tasks** with priorities, completion, filtering, and deletion.
- **Notes** with browser-local persistence.
- **Focus timer** with start, pause, reset, and completion notification when permission is already granted.
- **Email integration setup page** describing the secure connection workflow.
- Responsive layouts, a theme toggle, privacy notice, and clear-local-data action.

## Important: what is and is not connected

This is a **functional front-end starter**, not yet a fully connected autonomous AI agent.

- Chat replies are generated by local demo rules; no AI model API is called.
- Screen sharing displays the chosen screen in the page. The current demo does not send frames to an AI model for visual analysis.
- Voice relies on browser-supported speech APIs and may vary by browser/operating system.
- The email page is a setup guide only. No mailbox is accessed and no email is sent.
- Tasks, notes, and chat history are stored in this browser's localStorage. Avoid putting confidential work data in this demo.

Real AI reasoning, visual screen understanding, user authentication, and email access need a backend and properly configured integrations.

## Run locally

This version uses plain HTML, CSS, and JavaScript; no build step or package installation is required.

1. Clone the repository:
   ```bash
   git clone https://github.com/varun5812/Fit_Tracker.git
   cd Fit_Tracker
   ```
2. Serve the directory locally. For example, if Python is installed:
   ```bash
   python -m http.server 5500
   ```
3. Open http://localhost:5500 in a modern browser.

Use localhost or HTTPS for browser APIs such as screen sharing and microphone access. Speech recognition support differs between browsers.

## Suggested next implementation phases

1. **Backend and AI provider:** add authenticated API endpoints, model configuration via environment variables, streaming responses, rate limits, and error handling.
2. **Screen understanding:** send only user-approved screenshots/frames to a vision-capable model; make capture status visible and provide immediate stop/clear controls.
3. **Voice:** improve push-to-talk and interruption handling, add a robust speech-to-text/text-to-speech service, and expose microphone status.
4. **Work email:** integrate Gmail or another provider through OAuth with minimum necessary scopes. Start read-only; require review before sending or modifying messages.
5. **Security and reliability:** add authentication, authorization, tests, retention/deletion policies, and avoid logging message bodies, screenshots, or tokens.

## Security and privacy

- Never request or store a work email password, session cookie, or pasted access token.
- Keep model API keys, OAuth secrets, and refresh tokens on the server; never commit secrets or a real .env file.
- Work-account integrations may require employer or administrator approval. Follow your organization's policies.
- Treat emails and web pages as untrusted content, not instructions that can override user intent.
- Ask for explicit confirmation before sending emails or taking other consequential actions.
- Do not run silent screen or microphone monitoring. Use the browser's visible permission controls.
